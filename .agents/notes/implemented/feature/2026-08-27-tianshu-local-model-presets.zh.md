# Agent Note: 自定义提供方卡片上的本地模型接入预设

Status: implemented

[English](2026-08-27-tianshu-local-model-presets.md) | 中文

## Problem

产品正在扩展到互联网 API-key 提供方之外：所有者会在本地 GPU 上部署模型，局域网可达的 GPU 服务器也在范围内。harness 的模型层已经同时服务两者——`llm-pi-ai` 说 OpenAI 兼容协议，设置的模型页也已有手工声明提供方的卡片（`CustomProviderCard`），接受任意 base URL 并在 `{baseURL}/models` 探测模型。

缺的是知识而非能力：本地部署 Ollama、vLLM 或 llama.cpp 的用户需要知道各自运行时的惯用端口，并手工填写五个字段的声明——在产品现在想推广的路径上，这是摩擦。

## Decision

自定义提供方卡片开头加三个一键预设 chip——Ollama（`http://127.0.0.1:11434/v1`）、vLLM（`http://127.0.0.1:8000/v1`）、llama.cpp（`http://127.0.0.1:8080/v1`）。点击是**填写动作，不是状态、不是提交**：它设置路由 id、显示名和 base URL；原本的所有必填门槛（至少一个模型、可选密钥）照旧门控创建按钮。路由词干已被占用的预设 chip 自行禁用，而不是替用户造一个带后缀的 id——冲突由现有的字段级提示点名。

局域网 GPU 不需要专门入口：同一张卡片把服务器地址粘贴为 base URL 即是文档化的流程，README 已写明。

不附带任何模型层或 settings schema 改动。预设完全住在客户端卡片里（`LOCAL_PRESETS` 常量）；它们产出的 provider profile 与手工填写的声明逐字节相同，适配器、凭据和探测路径永远不会知道预设存在过。

## Consequences

本地运行时的用户点一下 chip、至多改个端口、拉取模型、创建提供方。局域网 GPU 用户粘贴 `http://<主机>:<端口>/v1` 走同一流程。

预设列表刻意只有三项，不是扩展面：端口是这些运行时默认安装的惯例，不遵守惯例的运行时仍由手工录入服务。日后新增预设 = 一个常量加两个 locale 键。

密码认证远程 GPU 的 SSH 隧道能力**有意不**在本次改动内：它是宿主侧插件（隧道生命周期、一次性密钥初始化、凭据存储），另行设计。本笔记只覆盖零基础设施路径。

## Alternatives considered

**专门的「本地提供方」卡片类型。** 否决：为纯粹的字段取值差异分叉声明面。卡片已校验本地声明所需的一切；第二张卡片只会与第一张漂移。

**卡片打开时自动探测本地运行时。** 否决：在设置表单里做端口扫描是有副作用的网络行为，且运行时还没跑起来（用户预配置的常见情形）时会报「未找到」，读起来像错误。

**chip 点击时探测。** 同理否决：点击必须保持纯填写，现有的「获取可用模型」按钮已按需探测端点并带真实错误报告。

## Testing

`provider-form.client.spec.tsx` 新增 `local runtime presets` 块：一例驱动 vLLM chip 并断言路由/显示名/base URL 已填（且未提交任何东西）；一例断言被占用的词干恰好禁用那一个 chip，相邻 chip 保持可用。包套件 231 项测试通过；`typecheck` 干净；客户端 bundle 已重建（`lib/client.js` 服务运行中的 web 应用）。
