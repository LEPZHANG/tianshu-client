# Agent Note: 专家套件落地——安装真正写出 skill，页面正式启用

Status: implemented

[English](2026-09-01-tianshu-suites-install.md) | 中文

## 问题

专家套件与技能两个页面此前是诚实的占位状态：本地的 `BUILTIN_SUITES` 表渲染出一批宿主毫不知情的卡片，安装什么也不做，技能页面列的是硬编码的五项。两个页面都没有连到真正决定一个会话拥有哪些 skill 的那个文件系统 skill 提供方。

## 决策

两个页面都成为可用界面，背后由一个新增的宿主包支撑。

- **`packages/skill/skill-suites`**（新增）：内置套件目录是一张随发行版交付的常量表——这是产品决策，不设远程来源——并持有其安装生命周期。安装会把每个内置的 SKILL.md 写到用户 skill（技能）根目录下（`$DSH_HOME/skills/<name>/SKILL.md`），卸载则删除它们。**安装状态就是文件是否存在，而不是一条存下来的记录**——手工删掉文件夹等同于卸载，重新安装是幂等的。卸载会保留用户编辑过的 skill，判据是与内置正文的 SHA-256 字节一致性。`list()` 在 `installed` 之外还投影出 `current`：某个 skill 已安装的正文不再等于本包随发行版交付的那一份时即为 false，而页面正是把这个状态变成一次重新装配。
- **三个 RPC**（`skill.suiteList` / `skill.suiteInstall` / `skill.suiteUninstall`）：每次变更都把重新投影后的目录作为自身回显返回，与工作区领域采用的全量快照姿态一致。错误码 `suite-not-found` 是新增的。已贯通完整的 13 处接线路径以及各个 fake。
- **专家套件页面**：由 RPC 驱动的卡片，带安装状态、安装／卸载按钮、在已安装套件的随发行版正文已经前进时出现的重新装配按钮，以及忙碌与失败状态。每张卡片都列出该套件的 skill，逐个给出显示标题、`/name` 命令和一行摘要，使卡片读起来像一份能力清单，而不是一个光秃秃的数字。本地的 BUILTIN_SUITES 表已退场；宿主目录是唯一真源。
- **技能页面**：存在当前会话时，目录来自宿主按会话寻址的 `skill.list`（中文标题与分类按名称从本地表合并进来）；没有会话时（或正在加载时），由随发行版交付的五个 skill 的目录顶上。「发送到对话」通过作用域内的插入文本事件预填输入框。

## 曾考虑的替代方案

**以写注册表的方式安装，而不是写文件。** 不采用：文件系统 skill 提供方是唯一的发现路径，因此安装进来的 skill 与手写的 skill 走的是同一扇门——既不存在第二条需要保持同步的录入通道，也不存在会与磁盘漂移的注册表状态。

**卸载时把该套件安装过的东西全部删掉。** 不采用：卸载绝不能毁掉用户的成果，因此哈希值不再等于内置正文的 SKILL.md 说明它在安装后被编辑过，会被保留。

**页面只保留安装与卸载两个动作。** 不采用：随发行版正文一变，这两个动作就不再覆盖全部状态。已安装的文件不再等于随发行版交付的那一份，于是卸载会把它当作用户自己写的而保留，而安装只在套件缺席时才提供——套件会停在旧正文上，没有任何动作能推动它。`current` 正是把这个状态与普通的「尚未安装」区分开的东西，而重新装配是解决它的动作。

**去掉技能页面的本地兜底，只读 `skill.list`。** 不采用：`skill.list` 按会话寻址——这是它唯一的设计约束——而一个管理界面不应当依赖于是否有打开的对话。

**从远程来源拉取套件目录。** 因产品决策而不采用：目录以常量表随发行版交付，因此页面在没有网络的机器上照样可用，而一个套件的内容也被钉在用户安装的那个构建上。

## 后果

安装状态即文件是否存在，这既让页面对被手工改过的 skill 根目录说真话，也意味着没有任何记录说明*某个文件夹是哪个套件写的*：被两个套件同时安装的 skill 只是一个文件，卸载其中任一个时，只要另一个仍以字节一致的正文内置它，该文件就会留下。

目录被钉在发行版上。新增或修订一个套件是一次发行代码改动，而不是一次内容更新——这正是「不设远程来源」这个决策的代价。

随发行版正文在已有安装之下的变更，会留下卸载不会删除的文件，因为它们不再等于随发行版交付的那一份。页面把该套件报为「有更新」并提供重新装配，而重新装配会重写该套件的每一个 skill；用户自己做过的编辑在这里与过期正文无从区分，因此这个动作同样会覆盖它，页面的安装说明写明了这一点。

## 测试

- `skill-suites`：7 项测试跑在真实临时目录上（安装写出的正文正是提供方会发现的内容；幂等性；保留编辑内容的卸载）。
- `skill-suites` 与 `ui-tianshu-brand` 还覆盖「有更新」的投影与解决它的动作：已安装正文不同（以及 SKILL.md 已消失）的套件报为已安装但不是最新，重新装配后回到最新。
- `apiproxy`：376 项全绿，含套件生命周期的完整往返。
- `ui-tianshu-brand`：55 项全绿——带安装状态的目录渲染、采纳回显的安装／卸载流程、带标题合并的宿主行桥接、无会话时的兜底。
- 全部涉及范围：896 项测试，`pnpm run build` 退出码 0。
