# 专家套件落地：安装真正写出 skill，页面正式启用

Date: 2026-09-01
Status: implemented
Scope: feature

[English](2026-09-01-tianshu-suites-install.md) | 中文

## 改动内容

专家套件与技能两个页面从诚实的占位状态变为可用界面，背后由一个新增的宿主包支撑。

- **`packages/skill/skill-suites`**（新增）：内置套件目录以随发行版交付的常量表形式存在（产品决策：不设远程来源），并持有其安装生命周期。安装会把每个内置的 SKILL.md 写到用户 skill（技能）根目录下（`$DSH_HOME/skills/<name>/SKILL.md`），卸载则删除它们。**安装状态就是文件是否存在，而不是一条存下来的记录**——手工删掉文件夹等同于卸载，重新安装是幂等的。卸载会保留用户编辑过的 skill（以内置正文的 SHA-256 判断字节是否一致）。
- **三个 RPC**（`skill.suiteList` / `skill.suiteInstall` / `skill.suiteUninstall`）：每次变更都把重新投影后的目录作为自身回显返回，与工作区领域采用的全量快照姿态一致。新增错误码 `suite-not-found`。已贯通完整的 13 处接线路径以及各个 fake。
- **专家套件页面**：由 RPC 驱动的卡片，带安装状态、安装／卸载按钮，以及忙碌与失败状态。每张卡片都列出该套件的 skill，逐个给出显示标题、`/name` 命令和一行摘要，使卡片读起来像一份真实的能力清单，而不是一个光秃秃的数字。本地的 BUILTIN_SUITES 表已退场：宿主目录是唯一真源。
- **技能页面**：存在当前会话时，目录来自宿主按会话寻址的 `skill.list`（中文标题与分类按名称从本地表合并进来）；没有会话时（或正在加载时），由随发行版交付的五个 skill 的目录顶上。「发送到对话」通过作用域内的插入文本事件预填输入框。

## 这些决策的理由

- **以文件方式安装，而非写注册表**：文件系统 skill 提供方是唯一的发现路径，因此安装进来的 skill 与手写的 skill 走的是同一扇门——既不存在第二条需要保持同步的录入通道，也不存在会与磁盘漂移的注册表状态。
- **按字节一致判定用户编辑**：卸载绝不能毁掉用户的成果；哈希值不再等于内置正文的 SKILL.md 说明它在安装后被编辑过，因此会被保留。
- **技能页面保留本地兜底**：`skill.list` 按会话寻址（这是它唯一的设计约束），而一个管理界面不应当依赖于是否有打开的对话。

## 不变式与测试

- `skill-suites`：7 项测试跑在真实临时目录上（安装写出的正文正是提供方会发现的内容；幂等性；保留编辑内容的卸载）。
- `apiproxy`：376 项全绿，含套件生命周期的完整往返。
- `ui-tianshu-brand`：55 项全绿——带安装状态的目录渲染、采纳回显的安装／卸载流程、带标题合并的宿主行桥接、无会话时的兜底。
- 全部涉及范围：896 项测试，`pnpm run build` 退出码 0。

## 延后事项

- 安装后输入框 `/` 菜单的实时刷新（提供方按自己的节奏重新扫描，页面不会强制触发）。
- 套件安装后无需重新加载即可刷新技能页面上的宿主行。
- 冗余的 `listCollections`／`listDeletedSessions` 客户端动作（此前已延后的事项）。
