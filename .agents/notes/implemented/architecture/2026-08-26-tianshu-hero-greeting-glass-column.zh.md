# Agent Note: 主视觉区改为个性化问候，侧边栏改为玻璃质感

Status: implemented

[English](2026-08-26-tianshu-hero-greeting-glass-column.md) | 中文

## 问题

产品所有者于 2026-08-26 结束多轮设计评审，对组装后的产品提出四点要求：侧边栏换更轻的质感（饱和的品牌蓝列观感沉重，选定方向是「更浅、半透明」）；用更温暖的主视觉问候语替换泛用的「您好」标题与「内测版」徽章；工作区 chip 移到输入卡下方，并处理成带浮起阴影的胶囊（QwenWork 的姿态）；输入卡停在会话列的垂直正中，而不是偏上。

hero 文本是组装后的浏览器输出，因此这里的每处改动都会体现在快照里；而依赖挂钟的问候语天生不确定，测试面必须随之迁移。

## 决策

**侧边栏 S4 质感。** `brand-tokens.ts` 现在给 `--dsw-specific-sidebar-fill` 喂入半透明色标：浅色主题为冰蓝玻璃，暗色主题为半透明藏青。`TianshuSidebar.module.css` 加上 `backdrop-filter: blur(18px)`，并翻转局部 ink 重绑：浅色主题下这一列是浅色表面，子树因此在玻璃上读作深藏青 ink；`body[data-ds-dark-theme]`（ui-theme 的规范暗色信号，绝不读主题 id）把同一批 token 重绑回白色族，因为暗色列仍是暗色表面上的半透明藏青。字标的光晕／延伸线对遵循同样的分主题处理（浅色玻璃上为 `#E2ECFC` 描边加藏青线，暗色下为白线加藏青光晕）。

**hero 问候。** `hero.headline`／`hero.preview` 已移除；标题现在是按时段的问候（5–12 上午，12–18 下午，其余晚上），第二行以弱化样式承载配套的发问：上午好，cxc / 有什么需要我来帮忙？用户名来自新增的 `GET /dsh-webui-auth/whoami`（加在本地的认证插件里）：有会话时返回 200 与会话用户名，无会话时返回 `{ok:false}`，认证关闭时返回 `{ok:true, username:null}`——绝不返回 404，未登录的浏览器因此不产生控制台网络噪音。ConversationRoot 每次挂载时通过一次微任务包裹的 fetch 解析一次（jsdom 安全，所有失败都被吞掉），再以 prop 交给 HeroShell；没有该认证面的宿主（桌面客户端、e2e harness）渲染泛用问候。名字拼接走 locale 键（zh `'，{name}'`、en `', {name}'`），由各语言持有自己的标点。

**工作区行移到卡下。** hero 工作区行（chip + agentPreset 座位）在 composer 栈里移到 InputBar 之后，chip 重绘为浮起的胶囊（`--dsw-specific-input-major` 填充、发丝边框、`--dsw-shadow-lv2`），与卡片左缘齐平。预设选择器保留在该行的座位——它仍然只在 hero 阶段出现，这是它被记录在案的约定（只有在会话尚无历史时才可选择预设）。

**卡片真居中。** hero 外壳在卡片上方渲染 72px、在工作区行下方渲染 32px，flex 居中的栈因此把卡片停在几何中心下方 20px；`.composerHero` 的 40px 底部内边距恰好抵消这 20px（该算术与卡片高度无关）。光晕锚点随卡片移动（bottom 92 → 136）。验证方式是用实现自身的 CSS 复刻出一个独立页面并测量：卡片中心落在列中心上，偏差 0.0px。

## 后果

组装后的 hero 输出变了，无密钥预期输出随之迁移：`normalizeAria` 把按时段的问候短语折叠为 `{{greeting}}`（与它的时钟规则属于同一类易变性折叠——问候是挂钟状态，不是回归面）；lifecycle-chrome 的 hero／plan-active 预期输出重排（工作区行现在跟在卡片之后），问候行拆成两个文本节点。e2e 的存在性检查改为锚定在稳定的发问行上，而不是旧标题；HMR 探针编辑挂钟当前显示的那个问候键；鱼形标记新增 `data-hero-fish` 锚点，因为文本选择器无法寻址一个随时钟变化的行。

whoami 端点是认证插件的第一个客户端可见面：它只披露调用者自己存活会话的用户名，绝不披露 token，并对每一种未认证状态都返回成功形状的响应体。

暗色主题是被承接而非重新设计：玻璃色标是色相匹配的近似，与既有暗色取值的姿态相同。

## 曾考虑的替代方案

**钉死 e2e 时钟，而不是归一化问候。** Playwright 的 clock API 可以为预期输出捕获冻结时段。不采用：暂停的时钟会冻结应用自身的计时器（tooltip、重连退避），恢复时钟也只是收窄竞态；问候确实是挂钟状态，而 `normalizeAria` 本就持有这一类折叠。

**把预设选择器移进 InputBar 的工具行。** 这样能匹配获批设计稿中卡片内部的位置。不采用：该座位按约定仅限 hero 阶段（会话一旦有历史，预设切换就会被拒绝），内联进输入条要么在活跃阶段显示一个失效控件，要么分叉该 slot 的渲染。

**通过全局 token 层为玻璃列覆盖 `--dsw-alias-*` ink。** 与此前同理不采用：该层落在 `body` 上，全局覆盖 ink 会重绘整个应用，而不是那一列。局部重绑（现在按主题分写）仍然是这里的 seam。

## 测试

包内套件通过：ui-conversation（29 个文件）与 ui-tianshu-brand（6 个文件）全绿，改动文件保持逐文件 100%（whoami 加载器的三种结局——有名字、无名字、无 fetch 面——各有一个打桩测试）。仓库 `typecheck` 干净。卡片居中补偿是在以实现自身 CSS 构建的页面上测量的（残差 0.0px）。e2e 预期输出已手工迁移到新的 DOM 顺序，合并前应在 `DSH_SNAPSHOT=refresh` 下复核。
