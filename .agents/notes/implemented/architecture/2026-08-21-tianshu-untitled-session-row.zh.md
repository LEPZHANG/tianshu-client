# Agent Note：未命名会话既不可读，又有两个名字

Status: implemented

[English](2026-08-21-tianshu-untitled-session-row.md) | 中文

## 问题

经 CDP 对运行中的桌面客户端做对比度扫描，发现 会话管理 页把空白会话的标签渲染在白色行上，对比度仅 **1.26:1**——远低于 AA 要求的 4.5:1，在截图里几乎完全看不见。

`.rowUntitled` 绑定了 `--dsw-alias-label-dimmed`。该标记是*占位符*文字色：在真实标签旁边使用是对的，作为一行仅有的标签则是错的。这一行没有其他文字，因此淡化抹掉的是整行内容，而非弱化其中一部分。

同一次扫描还在同一行发现第二个缺陷。页面把该会话称为 `未命名会话`；而侧边栏的工作区树把同一个会话称为 `新会话`。`ui-workspace` 的 `rows/Rows.tsx` 早已拥有这条规则——`node.blank ? t('session.new') : node.title`——本页却依据 `title === ''` 另造了一条平行规则。

## 决策

`.rowUntitled` 改用 `--dsw-alias-label-secondary`（5.8:1）并配以斜体。`label-tertiary` 先被实测并否决，其 3.71:1 仍未达 AA。斜体承担起「尚无标题」这一信号，颜色因而无需再承担它，于是该区分得以保留，且不依赖此表面无法提供的对比度。

标签遵循工作区树：`blank === true` 时命名为 `新会话` / `New Session`，与侧边栏对同一行的显示一致。空标题的兜底保留，因为「标题缺失」与「会话空白」是两个不同的事实，且两者都必须避免渲染出空行。

## 权衡结果

同一个会话现在在两个表面上读法一致。`page.sessions.untitled` 键名保持不变，取值改为共享措辞；该键描述的是行的状态，而非那段文字。

读取 `blank` 扩大了本页对会话摘要的依赖面，而该字段本就存在于其中。

## 备选方案

**全局调高 `--dsw-alias-label-dimmed`。** 可一次修好所有「淡色叠白底」的情形。否决：该标记属上游且被共享，在其旁边有标签的场合其占位符角色是正确的，改动它会波及本次工作未检查过的表面。

**保留 `dimmed`，改为给该行加背景底色。** 不动文字色即可达到 AA。否决：相对该缺陷而言机制过重，且会发明一种其他列表都不使用的行样式。

**两个名字都不动。** 它们分属不同表面，因此这种偏差尚可辩解。否决：它们列出的是同一批会话、来自同一个 store，而树的规则本就存在——第二个名字是意外，不是决策。

## 测试

一个测试断言：带有陈旧标题且 `blank: true` 的会话渲染为 `New Session` 而非该陈旧标题。已确认移除 blank 规则后它会失败，因此它钉住的是共享命名规则而非兜底逻辑。

对比度是依 WCAG 相对亮度公式计算的，而非目测：修复前 1.26，被否决的中间方案 3.71，修复后 5.8。

完整执行 `pnpm run build` 后在运行中的客户端验证：空白行计算为 `rgb(97, 102, 107)` 斜体，有标题的行为 `rgb(15, 17, 21)` 常规体。

包测试通过（37 个），per-file 100%。`typecheck` 与 `lint` 干净。

## 预设卡片上同一处标记误用

扫描在 Agent 预设 卡片上发现了完全相同的 1.26:1 失败：`ui-agent-preset` 中的 `.cardId`——即用户要填进配置的预设 id——同样绑定了 `label-dimmed`。

对 `packages/client` 中全部 `label-dimmed` 用法的普查确定了该标记的用途：在其余十一处，它无一例外用于 `::placeholder`、`:disabled` 与 `border-color`。`.cardId` 是唯一用它来渲染普通可读文字的地方。

它改用 `label-secondary`，理由与 `.rowUntitled` 相同。`label-tertiary` 先被尝试——那正是同一文件中 `.badge` 与 `.intro` 所用——但浅色模式下实测为 3.71:1。两种模式均在运行中的客户端上实测而非推算：浅色 `rgb(97,102,107)` 叠白底为 5.8:1；深色 `rgb(207,211,214)` 叠 `rgb(44,44,46)` 为 9.25:1。

该包的 157 个测试全部通过。此文件未做其他改动。
