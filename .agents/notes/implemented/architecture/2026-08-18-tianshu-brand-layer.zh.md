# Agent Note: Tianshu brand layer as an added client plugin

Status: implemented

[English](2026-08-18-tianshu-brand-layer.md) | 中文

## 问题

本检出是 DeepSeek Harness 的下游部署，以另一个身份交付：「天枢平台」。产品外观必须是它，而不是 dsh。

同时，本检出是上游的纯净镜像，零自有提交，而上游几乎每天提交——一次同步就拉入 111 个 commit。若通过直接编辑承载 dsh 身份的文件来换肤（`ui-theme` 的 token 表、`ui-sidebar` 的外壳、`ui-primitives` 的品牌图形），本地改动就正好落在上游改动最频繁的文件里，此后每次 `git pull` 都变成一场围绕表现层的合并谈判。

因此要求是双面的：产品要换成新品牌，且换肤不得在上游文件里堆积冲突面。

## 决策

品牌集中在一个新增包 `@deepseek-ai/dsh-client-ui-tianshu-brand` 中，通过既有扩展点贡献，而非编辑上游文件。

**颜色走 token 覆盖层，不改样式表。** 该包以自身包名作为层标识调用 `ctx.theme.overrideTokens`。层里只放 Tianshu 值与上游主题不同的 token：侧边栏列填充（竖向品牌蓝渐变）与品牌文字色。`--dsw-specific-sidebar-fill` 是被文档化的可覆盖 token，且接受任意 CSS 背景值，渐变可直接骑在它上面。品牌蓝是天枢蓝 `#2563EB`，即平台指定的主色。它与上游的 `--dsw-static-deepseek-500`（`rgb(65,118,230)`）接近但不相同，因此取值是钉死的，而非别名到该静态色。

**列内 ink 走局部重绑，不做全局覆盖。** token 覆盖层会落成 `body` 上的内联自定义属性，因此在那里覆盖中性 ink 族会重绘整个应用，而不是那根蓝色列。改为由 `TianshuSidebar.module.css` 在自己的 `.root` 上重绑 ink、边框、交互与导航项 token 族，嵌套其中的一切自动继承反色刻度，无需知道自己身处品牌蓝之上。这是对上游侧边栏已用于滚动条的局部重绑范式的沿用。

滚动条间接对仍绑定 ui-theme 门禁要求的规范 `l2` 写法；列真正重绑的是该对最终解析到的两个 `--dsw-alias-scrollbar-*-l2` 高度 token。这样嵌套列表能在蓝底上画出浅色滑块，而无需本列对间接对做特例。

**侧边栏是替换，不是扩展。** `sidebar` 是 `single` 插槽，注册进去会顶替上游外壳而非叠加，并连带移除该外壳声明的子插槽。因此本包在自己 register 的 `children` 中认领 `sidebar.workspaces`、`sidebar.settings`、`sidebar.footer.action`，使 ui-workspace 的浏览区与 ui-settings 的底部座位原样可用；web-app bundle 禁用 `ui-sidebar` 行，保证同时只有一个外壳存活。

三处**类型**声明是通过 type-only 导入复用 ui-sidebar 的，而非重新声明。`SlotMap` 是跨整个编译单元的声明合并接口，因此即便两个插件永不同时挂载，同一 key 的第二次声明仍会与上游那份相撞——`gen-client-catalog` 会拒绝这种重复，因为它无法判定哪份文档描述的是存活的插槽。运行期授权仍来自本包自己的 `children`，那才是插槽内核实际校验的东西。由此产生的依赖同时是一根绊线：若上游改动这三个规格之一，本包会编译失败，而不是无声漂移。

替换后逐字保留了上游列的结构性行为——折叠的滑移加交叉淡出、淡出期间冻结展开宽度、跟随指针的滚动条——并在「新建会话」与浏览区之间加入设计稿的导航块（配置 / 任务管理 / 会话管理）。

**产品标识字符串**位于三处没有扩展点的上游文件：`apps/web/index.html`（标题，`DocumentTitle` 会把会话标题拼接其上）、`apps/web/public/manifest.webmanifest`，以及每个客户端包都需要的 `tsconfig.base.json` 路径行与两处 bundle 注册行。它们都是追加位置上的单行改动。

**管理界面同在本包内。** 侧边栏导航（配置 / 任务管理 / 会话管理）打开的页面注册进 `shell.overlay`，二者共享的选中态是在 `apply` 中铸造一次、同时交给**两个注册**的 store 句柄。若把页面拆成独立包，就需要一条跨包传递该选中态的通道，而客户端规则并不提供——被认可的路径只有插槽与 ctx 服务，两者都不承载跨插件的响应式状态。于是：一个包，一个句柄，不发明新接缝。

overlay 层覆盖整个 frame（含侧边栏），因此页面被布局成两列网格，第一列留空且点击穿透。覆盖住侧边栏会把用户困在页面上，因为关闭它的导航正在那里。该列宽度来自侧边栏发布的一个自定义属性，其值是 frame 本就交给它的宽度，因此拖拽或折叠时页面会跟着列走，且不重复声明任何几何量。

## 备选方案

**直接改 `design-platform.css` 与 `SidebarRoot.tsx`。** 这是抵达同样像素的最短路径，落选原因是维护而非正确性：这些文件属于上游修订最频繁之列，品牌会在每次同步时与来件相撞。token 覆盖接缝的存在意义，正是把某个部署的配色挡在主题表之外。

**全局覆盖中性 ink token，而非在 `.root` 上重绑。** 这能省掉样式表里的重绑块，但覆盖层是文档级的：全局反转 `--dsw-alias-label-primary` 会让会话列变成白底白字。只有这一根列换了背景，重绑就该属于这根列。

**把导航贡献进侧边栏子插槽，保留上游外壳。** 这本可避免替换整列，但「新建会话」与浏览区之间没有子插槽——那条带子归外壳自身的几何所有。注册进 `sidebar.workspaces` 会把导航塞进 ui-workspace 拥有的区域，并顶掉会话浏览器。

**用 `--patch` 覆盖层或独立 profile，而不改 bundle。** 用户补丁层可以在不碰 `cordis.patch.yml` 的前提下禁用并插入行，能让 bundle 保持原样。未采用的原因是：品牌是这个检出的**本体**，不是某台机器上的偏好；覆盖层文件需要随产品分发并在每次启动时传入，否则 `dsh web` 会以未换肤状态启动。

**改写 `ui-primitives` 里的上游品牌图形。** `BrandWordmark` 与 `FishLogo` 都吃 `currentColor`，本可换成新的路径数据，但它们是上游文件，且改动会连启动门与其他所有消费者一并换肤，无从退出。Tianshu 图形改放在新包中。

## 权衡结果

今后上游同步只会在上表所列文件同时被上游修订时冲突，而每一处都是追加位置的单行改动。品牌的实质——配色、图形、列、导航、文案——都落在上游没有的文件里。

代价是侧边栏如今是上游外壳的一份分叉，而非它的一种配置：上游对 `SidebarRoot.tsx` 的修复不会流到 `TianshuSidebar.tsx`，须人工回植。这是设计稿在结构上偏离上游列所必须付的价钱，也正因如此，外壳的折叠与指针滚动条行为被逐字保留而非重做——漂移越小，回植越便宜。

复用上游插槽声明意味着本包无法与 `ui-sidebar` 并存，只能取而代之，并且对一个它所替换的包持有类型级依赖。这种耦合是有意的：正是它让上游对那三个规格的改动在此处变成编译错误。

导航行会打开本包所拥有的管理页，它们注册进 `shell.overlay` 而非 `conversation`——后者是 ui-conversation 所拥有的单一插槽，占用它会顶掉聊天界面。由于 overlay 覆盖整个框架，页面是一个双轨网格，第一轨属于侧边栏，留空且点击穿透，使关闭页面的导航始终可达；该轨宽度来自侧边栏发布的一个自定义属性，因此无需在别处重述。

这些页面能展示什么，受限于宿主实际具备的能力，而这条边界是写在页面上而非伪造出来的：模板中心仅为呈现，因为宿主没有模板概念；任务管理不列出任何内容，因为宿主的定时能力是会话内的模型提醒而非跨会话表；会话管理列出真实会话但不提供任何变更操作；配置指向设置页而不复制它。四项均记入该包的 Known Limitations。

暗色主题可用但未经设计：参考稿只覆盖浅色，因此暗色列的取值是同色系近似，而非既定配色。

## 测试

`packages/client/ui-tianshu-brand/tests/` 覆盖注册（插槽占位、重新声明的子座位、注入回调、token 层的来源与双模式取值，以及卸载时逐项移除）、外壳行为（新建会话路由、折叠沉降、wide 标志送达每个座位、两种列宽下的导航选中）、导航 store（选中、再次点击关闭的规则，以及跨实例不做持久化）、页面（各目的地的内容、诚实的空状态与提示、真实会话行，以及关闭）与指针滚动条状态机。本包达到 per-file 100%。

ui-theme 的仓库级滚动条门禁覆盖了本包样式表：它拒绝了本列最初自定义滑块颜色的写法，上文的高度 token 重绑正是由此而来。
