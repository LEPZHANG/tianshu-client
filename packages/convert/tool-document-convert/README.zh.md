# @deepseek-ai/dsh-tool-document-convert

[English](README.md) | 中文

面向模型的 `convert_document` 工具。它把一次调用点名的路径相对会话工作区解析出来，判定该会话是否可以写入输出文件，再把转换本身交给[文档转换 seam](../document-convert/README.md)（`ctx.documentConvert`）。

这是 **Consumer** 包。它拥有 schema、各项防护检查与呈现；路由选择归 seam 所有，转换器归提供方所有。它是 function／namespace 插件（`inject: ['tools', 'systemPrompt', 'documentConvert', 'fs']`）。

## 参数

| 参数 | 必填 | 含义 |
|---|---|---|
| `path` | 是 | 要转换的文件，由文件系统后端解析。 |
| `to` | 是 | 要产出的格式，取值是 seam 十三种格式构成的枚举。注册表会在执行前拒绝其他任何取值，因此模型无法索要一种不可能存在的格式。 |
| `output_path` | 否 | 写入位置。默认为源文件路径换上新扩展名。 |
| `if_exists` | 否 | 输出路径已被占用时怎么办：`rename`（默认）写到它旁边并报出新名字，`overwrite` 替换它，`refuse` 让本次调用失败。 |

## 调用的执行顺序

1. 解析现行的文件影响策略：必须在触碰任何路径之前完成，因为一次转换必定产生文件。
2. 通过 `ctx.fs` 相对会话工作区解析源文件，并确认它存在且是普通文件。
3. 以同样的方式解析输出路径，并按沙箱模式检查它。
4. 对已被占用的输出路径施行 `if_exists`：在 `report.pdf` 旁边写出 `report-1.pdf` 并报出 `renamed_from`、替换该文件，或者以 `CONVERT_OUTPUT_EXISTS` 拒绝。改名最多尝试 100 个备选名，之后以同一个错误码拒绝，因此一个满是同名文件的目录换来的是一条消息，而不是无界的扫描。
5. 请求 seam `resolve` 出一份计划，再 `run` 它，并转发本次调用的取消信号。

seam 收到的两端路径都来自 `ctx.fs.processPath(...)`，即执行世界中的真实路径；结果报告的则是 `displayPath`，也就是模型点名的那个路径。

## 转换可以写到哪里

seam 不是一道限制边界：它的提供方把 argv 交给 `ctx.subprocess`，因此转换器以 harness 进程自身的权限写文件，在它与目标位置之间没有任何文件系统后端。真正作出这项决定的地方是本工具。

| 现行模式 | 结果 |
|---|---|
| 未挂载沙箱策略 | 没有基于根目录的限制；该组合不作任何限制。 |
| `read-only` | 一律拒绝。转换没有可退守的只读形式。 |
| `workspace-write` | 输出路径必须解析到会话工作区根目录之内。 |
| `danger-full-access` | 没有基于根目录的限制，该模式已经移除了它。 |

两种拒绝都是 `CONVERT_SANDBOX_DENIED`。本工具不公布任何升权参数：与编辑文件不同，请用户为一次转换放宽沙箱并无成例。

## 规范值

```
{ path, from, to, fidelity, steps: [{ from, to, provider }], bytes, notes: [{ code, message }], renamed_from? }
```

Code Mode 直接读取该值。渲染文本以文字陈述同样的事实：多步计划途经的中间格式，以及这次转换让文档付出了什么代价。

`renamed_from` 只在所请求的路径已被占用、转换写到了它旁边时才出现，其中是这次调用原本索要的路径。默认值之所以是 `rename`，是因为另一种做法会让失败的工具调用成为发现冲突的唯一途径：在模型尝试之前没有任何东西告诉它某个路径已被占用，于是一次拒绝不是安全提示而是试探，而旁观的用户看到的是一次转换为一个从未面临风险的文件失败了。两种做法都不会动已存在的那个文件，渲染文本还会要求模型把实际写出的名字告诉用户。

第二部分来自 `notes`。每个提供方都会报告自己这一步实际做了什么：CSV 导出只保留了一张工作表，PDF 抽取取回了页面文字但没有结构，HTML 结果是重排而不是分页；渲染文本把这些句子列在 **What this conversion did not carry over:** 之下。只有当一条有损路由什么都没报告时，文本才退回到那句通用说法：文字保留了下来，版式、样式和结构没有。具体的那句话模型可以直接转述给用户，通用的那句只是提醒它措辞留有余地。

## 呈现

待处理调用使用带 `kind: 'edit'` 的 `generic` 卡片，产出文件正是凭这一点进入已完成轮次末尾的产出文件行；`locations` 点名的是所请求的输出文件，使编辑器可以跟随定位，而这已是一个纯粹由参数决定的函数所能说的全部——改名要到执行期才定下来。完成卡片以实际写出的文件为标题，并在适用时标记 `(lossy)`；这些都取自持久结果元数据，因此回放能够重现。

## 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `timeoutMs` | `120_000` | 协作式工具调用预算，由 [`dsh-tool-call-timeout-policy`](../../guard/timeout-policy/README.md) 强制执行。默认值较大，因为 LibreOffice 冷启动要花掉数秒才开始读取文档，而多步计划每一步都要付这笔开销。 |

## 模型体验

### 系统提示词

#### 模型看到的内容

一个固定段落：只要本包被加载，就以 112 的顺序注册。

##### 转换指引

```markdown
Use the convert_document tool to convert a file between document, spreadsheet, and presentation formats. It reports whether the conversion preserved the source or only its text; say so when it did not, and never claim a conversion the tool refused.
```

#### Token 影响

每次请求一个固定段落，不随宿主装了哪些转换器而变；即使作用域限制隐藏了本工具的 schema，该段落仍然存在。

#### KV Cache 影响

在本包挂载期间保持静态，因此它留在可复用的提示词前缀中；只有挂载或卸载该插件才会改变它。

### 工具 schema

#### 模型看到的内容

生成的 [`convert_document` schema](../../../docs/tool-catalog.md#deepseek-aidsh-tool-document-convert)。`to` 枚举逐字列出 seam 的十三种格式，因此对外公布的词汇与宿主装了哪些转换器无关。工具调用预算是部署设置，不是模型参数。

#### Token 影响

每次请求承担固定的 schema 成本；作用域限制会移除 schema，但保留提示词段落。

#### KV Cache 影响

前缀稳定：schema 由本包自己的格式清单构建，其文本不随宿主状态变化，因此一个不可用的转换器不会使复用失效。

### 转换结果

#### 模型看到的内容

一行文字，点名所涉格式、写出的路径、它的字节大小，以及路由经过的提供方。多步计划会补上它途经的中间格式。有损路由随后补上代价：其提供方报告的备注，在「What this conversion did not carry over:」之下每条一行；若一条备注都没有报告过，则是那句关于版式和结构的通用说法。拒绝则携带 seam 或本工具自己的消息：无法到达的格式对会点名两端格式和步数上限，受损的源文件会点名导致失败的条目，扫描版 PDF 会说明必须先用 OCR 识别，沙箱拒绝会说明输出文件可以放在哪里。

#### Token 影响

每次成功调用几行短文本，其长度与步数及这些步骤报告的备注条数成正比，而与文档本身无关；转换后的字节绝不进入上下文。

#### KV Cache 影响

仅追加：每个结果都追加在产生它的调用之后，不会替换更早的请求 token。

## 已知限制与暂缓事项

- **直接调用 seam 会绕过这些防护。**源文件检查、工作区限制和冲突处置策略都位于本工具之内，因此同进程中直接访问 `ctx.documentConvert` 的调用方一项也得不到。把强制执行下移到提供方需要一套受沙箱约束的 spawn 安排，seam 已将其记录为暂缓事项。
- **冲突检查不是原子的。**存在性在转换开始之前就已检测，因此在这段间隙里于目标位置新建的文件，在 `overwrite` 下仍会被替换，在 `rename` 下也会被写掉。堵上这个缺口需要一次独占创建握手，而 seam 当前的输出路径约定还表达不了它。
- **没有升权通路。**在 `read-only` 下本工具直接拒绝，不像文件工具那样公布放宽模式后再重试的做法。如果真有部署需要从只读会话发起转换，升权词汇在 `dsh-sandbox` 中已经存在，本工具接入即可。
- **输出目录必须已经存在。**在 `out/` 不存在时点名 `out/final.pdf` 的调用，会以转换器自己的诊断失败，而不是给出一句明确的拒绝，因为没有任何步骤会创建中间目录。
