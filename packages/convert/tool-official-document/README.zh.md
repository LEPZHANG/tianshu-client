# @deepseek-ai/dsh-tool-official-document

[English](README.md) | 中文

面向模型的 `write_official_document` 工具。它以结构化字段接收一篇党政机关公文的文字内容，拒绝 GB/T 9704—2012《党政机关公文格式》不允许的写法，把其余内容按标准规定的版面排布，再写出文件。

这是[文档转换 seam](../document-convert/README.md) 的**第二个 Consumer**。它自己写出一种格式：OpenDocument 文本，即由本包组装的若干 XML 部件打包成的 ZIP；其余每一种格式都靠把这个文件交给 `ctx.documentConvert` 得到。它是 function／namespace 插件（`inject: ['tools', 'systemPrompt', 'documentConvert', 'fs']`）。

## 为什么做成工具而不是提示词

提示词可以教会模型按公文的写法行文：选定文种，用发文机关 + 事由 + 文种组成标题，写明主送机关，把正文分为一、／（一）／1.／（1）几级。它无法让文件真的成为 156 × 225 mm 版心上的三号仿宋。标准是一组尺寸：A4 纸、37 mm 天头、28 mm 订口、每面 22 行、每行 28 字、发文字号下 4 mm 处一条 0.35 mm 的红色分隔线、版心之下 7 mm 处的页码；而尺寸是由写出它们的代码产生的，不是由要求它们的文字产生的。

于是分工如此：模型负责文字，本工具负责版面。

## 参数

`output_path`、`title` 和 `body` 为必填；其余每一项都是标准容许的一个要素，公文或者携带它，或者不携带。

| 参数 | 条款 | 含义 |
|---|---|---|
| `output_path` | — | 写入位置，由文件系统后端解析。 |
| `title` | § 7.3.1 | 标题，通常为发文机关 + 事由 + 文种。 |
| `body` | § 7.3.3 | 正文，按顺序每段一个 `{ level?, text }`。工具负责补上各层次的层次序数与字体。 |
| `format` | — | `docx`（默认）、`odt`、`doc`、`rtf`、`pdf`、`html`、`txt`。当 `output_path` 的扩展名正好是本工具能写出的格式时，默认取该扩展名。 |
| `copy_number` | § 7.2.1 | 份号，排为六位数字。 |
| `secrecy` | § 7.2.2 | 密级和保密期限，写作 `{ level, period? }`，排为秘密★5年。 |
| `urgency` | § 7.2.3 | 紧急程度，特急或加急。 |
| `issuer` | § 7.2.4 | 发文机关标志，以红色排在页面上端。 |
| `doc_number` | § 7.2.5 | 发文字号，形如机关代字〔年份〕序号号。 |
| `signer` | § 7.2.6 | 签发人。它一旦出现，该公文即为上行文，发文字号随之移到同一行的左侧。 |
| `main_recipient` | § 7.3.2 | 主送机关；工具负责把它们连接起来并加上冒号。 |
| `attachments` | § 7.3.4 | 附件说明；只有一件时写作 附件：×××，多件时逐件编号并悬挂对齐于第一行之下。 |
| `signature` | § 7.3.5.2 | 发文机关署名，居中排在成文日期之上。 |
| `date` | § 7.3.5.4 | 成文日期，写作 `YYYY-MM-DD`，排为 2026年9月1日。 |
| `note` | § 7.3.6 | 附注；工具负责加上圆括号。 |
| `copy_to` | § 7.4.2 | 抄送机关，位于版记之中。 |
| `printer` | § 7.4.3 | 印发机关和印发日期，写作 `{ agency, date }`，是版记的最后一行。 |
| `overwrite` | — | 输出文件已存在时将其替换。默认为 false。 |

## 调用的执行顺序

1. 解析现行的文件影响策略：必须在触碰任何路径之前完成，因为这次调用必定产生文件。
2. 通过 `ctx.fs` 解析 `output_path`，按沙箱模式检查它，并在未设置 `overwrite` 时拒绝覆盖已存在的文件。
3. 按标准校验这篇公文。违规在此处抛出，**在写出任何内容之前**。
4. 在内存中构建 `.odt`：`content.xml`、`styles.xml` 和 manifest（元数据清单），打包为 ZIP，其中 `mimetype` 存放在最前且不压缩。
5. `format` 为 `odt` 时直接写入输出路径；否则先在本工具自有的临时目录中暂存，再请 seam 把它转换到位，两条路径都会删除暂存副本。

## 公文可以写到哪里

seam 不是一道限制边界，而且本工具是用 `node:fs` 写出 `.odt` 的，因此限制决定在这里作出，与 `convert_document` 的做法完全一致：两个工具共用同一份实现，由 [`tool-document-convert`](../tool-document-convert/README.md) 导出。

| 现行模式 | 结果 |
|---|---|
| 未挂载沙箱策略 | 没有基于根目录的限制；该组合不作任何限制。 |
| `read-only` | 一律拒绝。写出公文没有可退守的只读形式。 |
| `workspace-write` | 输出路径必须解析到会话工作区根目录之内。 |
| `danger-full-access` | 没有基于根目录的限制，该模式已经移除了它。 |

## 拒绝标准不允许的公文

标准中有若干条规则是对写法本身的禁止：发文顺序号不加「第」字，也不编虚位（§ 7.2.5）；日期用阿拉伯数字，年份标全，月份不编虚位（§ 7.3.5.4）；附件名称之后不加标点符号（§ 7.3.4）；份号不超过六位数字（§ 7.2.1）；正文的层次序数最多四级（§ 7.3.3）。违反其中任何一条的文件，不是一篇略有瑕疵的公文，而根本就不是公文。

所以这次调用直接失败，而不是排出一份通不过审核的文件，并且消息会点名条款。之所以要点名，正是因为：被告知违反了 § 7.2.5 的模型会去改那个字段，而只被告知调用失败的模型会把同样的值再发一遍。所有违规都会先收集齐再抛出，因此一次往返就报出全部需要修正的字段。`OFFICIAL_DOC_FIELD_MISSING` 表示必填字段为空；`OFFICIAL_DOC_FIELD_INVALID` 表示已填写的字段采用了标准不允许的写法。

本工具不检查的，正是标准交由人来判断的部分：文种选得对不对，标题是否三个部分齐全，主送机关是不是本该收文的单位。这些属于作者。

## 规范值

```
{ path, format, fidelity, bytes, elements: ['§ 7.3.1 标题', ...], notes: [{ code, message }] }
```

`elements` 点名成文后的公文实际对应的各项条款，顺序与 § 7 的编排一致。Code Mode 直接读取该值；渲染文本以文字陈述同样的事实。

`notes` 总是以 `OFFICIAL_DOC_FONTS_REQUIRED` 开头（原因见下文的限制），转换得到的格式随后再追加转换自身的提供方所报告的内容。

## 呈现

待处理调用使用带 `kind: 'edit'` 的 `generic` 卡片，产出文件正是凭这一点进入已完成轮次末尾的产出文件行；`locations` 点名输出文件，使编辑器可以跟随定位。完成卡片以写出的文件为标题，并在适用时标记 `(lossy)`；这些都取自持久结果元数据，因此回放能够重现。

## 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `timeoutMs` | `120_000` | 协作式工具调用预算，由 [`dsh-tool-call-timeout-policy`](../../guard/timeout-policy/README.md) 强制执行。写出 `.odt` 只需几毫秒；其余每种格式都要再付一次 LibreOffice 冷启动的代价，预算真正花在那里。 |

## 模型体验

### 系统提示词

#### 模型看到的内容

一个固定段落：只要本包被加载，就以 113 的顺序注册。

##### 公文指引

```markdown
Use the write_official_document tool to produce a 党政机关公文 laid out to GB/T 9704—2012. Write the wording yourself — the 标题 as 发文机关+事由+文种, the 主送机关, and the 正文 divided into levels — and let the tool set the page. It refuses a document that breaks the standard and names the clause; fix that field and call again. Repeat its notes to the user rather than claiming the file is printable as it stands.
```

#### Token 影响

每次请求一个固定段落，不随宿主装了哪些转换器而变；即使作用域限制隐藏了本工具的 schema，该段落仍然存在。

#### KV Cache 影响

在本包挂载期间保持静态，因此它留在可复用的提示词前缀中；只有挂载或卸载该插件才会改变它。

### 工具 schema

#### 模型看到的内容

生成的 [`write_official_document` schema](../../../docs/tool-catalog.md#deepseek-aidsh-tool-official-document)。每个可选参数都以它所满足的条款来描述，因此模型是按标准对要素的称呼来选择的，而不是从字段名去猜。`format` 枚举列出的是一个 OpenDocument 文本文件能够到达的七种格式，而非 seam 的十三种，因此模型无法索要电子表格。

#### Token 影响

每次请求承担固定的 schema 成本。它是转换系列中最大的一份 schema，因为标准有十六个要素，而每个要素的描述都要点名其条款；作用域限制会移除 schema，但保留提示词段落。

#### KV Cache 影响

前缀稳定：schema 由本包自己的要素清单构建，其文本不随宿主状态变化，因此一个不可用的转换器不会使复用失效。

### 结果

#### 模型看到的内容

先是一行文字，点名写出的路径、格式和它的字节大小；接着是这篇公文所对应的条款，使模型能够告诉用户文件实际携带了哪些要素；再接着是文件没有交付的部分，其中始终包含字体备注，转换得到的格式还包含转换所报告的内容。拒绝会一次点名全部被违反的条款；若宿主无法到达所请求的格式，则说明这一点，并点名 `format: "odt"`，作为无需转换器也能拿到文件的办法。

#### Token 影响

每次成功调用几行短文本，其长度与公文携带的要素数量成正比，而与公文的篇幅无关；公文的字节绝不进入上下文。拒绝的长度与被违反的条款数量成正比。

#### KV Cache 影响

仅追加：每个结果都追加在产生它的调用之后，不会替换更早的请求 token。

## 已知限制与暂缓事项

- **字体只写名称，不嵌入。**GB/T 9704—2012 规定了所用字体：方正小标宋简体、仿宋_GB2312、黑体、楷体_GB2312、宋体；文件按名称索要它们，在装有这些字体的机器上这是正确的。没有哪种格式能补上一台机器缺失的字体，因此没有这些字体的阅读方会替换成别的字体，于是字形不再是标准规定的那些，尽管每一项尺寸仍然是。所以每个结果都携带 `OFFICIAL_DOC_FONTS_REQUIRED` 备注。探测宿主已装字体以给出更精确的警告，需要一套跨平台字体查询，本仓库尚不具备。
- **无法生成印章。**§ 7.3.5.1（加盖印章的公文）与 § 7.3.5.3（签发人签名章）都要求一幅红色印章图像，而印章是发文机关本身的实物，不是排版引擎能够合成的东西。本工具产出的是 § 7.3.5.2，即不加盖印章的形式：发文机关署名居中排在成文日期之上；必须盖章的公文只能在事后另行加盖。
- **除 `odt` 外的每种格式都需要 LibreOffice。**默认格式是 `docx`，它经由 `ctx.documentConvert` 得到文件，因而也经由 `soffice`。在没有装它的宿主上，调用会以 `OFFICIAL_DOC_FORMAT_UNREACHABLE` 失败，并点名 `format: "odt"` 这个本工具自己就能写出的格式。选择这个默认值，看的是收文方打开的是什么，而不是每台宿主能产出什么。
- **版记是随正文排下来的，不会固定在最后一面的下端。**§ 7.4.1 要求版记位于最后一面的下端；而 ODF 文本是流式排版的，没有哪个段落属性能把一个块钉在它所落入那一页的底部。版记写在最后，所以它确实在最后一面上，但它上方留多少空白，取决于正文排完后剩下多少。解决这一点需要一个锚定到页面的框，而这会改变下游每个转换器处理这一部分的方式。
- **第 10 章的三种特定格式尚未实现。**信函格式、命令（令）格式和纪要格式各自用自己的排布替换版头。本工具只产出第 5 章至第 9 章规定的通用格式；一次本该产出纪要的调用会得到一份格式正确的通用格式公文，而那是一份错误的公文。
- **覆盖检查不是原子的。**存在性在构建公文之前就已检测，因此在这段间隙里于目标位置新建的文件仍会被替换：与 `convert_document` 是同一个缺口，原因也相同。
