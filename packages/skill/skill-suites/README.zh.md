# @deepseek-ai/dsh-skill-suites

[English](README.md) | 中文

内置专家套件目录：每个套件是一组 skill（技能），安装时会把随包分发的 SKILL.md 正文写入用户 skill 根目录。

## 模型

- 套件表是随包交付的常量（`src/catalogue.ts`）；套件没有远程来源（产品决策）。
- 安装会把每个随包分发的 skill 写入 `$DSH_HOME/skills/<name>/SKILL.md`。**安装状态就是文件是否存在**：不另存记录，因此手动删掉目录即等于卸载，重新安装也是幂等的。
- skill 可以声明随包资源：放在 `assets/` 下的文件，安装时写进 skill 目录、与 SKILL.md 并列。文件系统提供方把该目录报为 skill 的资源基目录，所以正文只写文件名，模型自会解析。数据可视化 skill 借此随包带上 ECharts，它产出的图表页从磁盘加载这个库，而不是从 CDN。
- `list()` 报出 `installed`（每个 skill 目录都在）与 `current`（每个已安装 SKILL.md 的哈希都等于本包当前随包正文）。从旧正文装出来的套件是「已安装但不为最新」，客户端据此给出重新装配；被用户编辑过的文件报出来完全一样，重新装配会把两者都覆盖。
- 卸载只删除其中 SKILL.md 的哈希仍与随包正文一致的目录；被用户编辑过的 skill 得以保留。因此随包正文变更后遗留下来的 skill 无法被卸载，只能被重新装配覆盖。
- 本包从不触碰 skill 注册表：文件系统提供方（`dsh-skill-filesystem`）在下一次扫描时发现已安装的 skill，与手写 skill 走的是同一条路径。

## 模型体验

间接：经由安装写入的 skill 文件——`dsh-skill-filesystem` 在下一次扫描时发现它们，`dsh-tool-skill` 随后编目并渲染，与手写 skill 的处理完全一致。

#### KV Cache 影响

安装或卸载会改变下一次请求前缀所携带的 skill 目录，使缓存前缀从目录消息起失效；本包自身既不组装也不发送请求。

## 已知限制与暂缓事项

- 安装不会强制提供方重新扫描：composer 的 `/` 菜单按提供方自身的扫描节奏反映新安装的 skill，而不是立即反映。
- 目前只交付一个套件（`office-essentials`，含六个 skill）；套件表是新增套件的唯一位置。
- 在随包资源出现之前就装过的 skill 仍被报为已安装，因为安装状态只看目录是否存在。它的目录里没有资源文件，直到该套件被再安装一次——届时凡与随包字节不符的都会被重写。
