# @deepseek-ai/dsh-client-ui-tianshu-brand

[English](README.md) | 中文

天枢平台的品牌层。它贡献两样东西：一个承载平台身份的主题 token 覆盖层，以及取代上游外壳的品牌侧边栏。

本包是本分叉的品牌 seam。它的存在是为了让平台的视觉身份集中在一个新增包里，而不是散落成对上游文件的编辑，从而使今后从上游 `git pull` 不产生冲突。

## Token 层

`brand-tokens.ts` 以本包名作为层标识，通过 [`ctx.theme.overrideTokens`](../ui-theme/README.md) 在当前主题之上叠加一层。层里只放 Tianshu 值与上游主题不同的 token：目前是侧边栏列填充（浅色主题为冰蓝半透明玻璃渐变，暗色为半透明藏青玻璃）与品牌文字色。`--dsw-specific-sidebar-fill` 是被文档化的可覆盖 token，且接受任意 CSS 背景值，渐变可直接骑在它上面。该层是全局的，因此只承载身份；需要在玻璃列**内部**改变的 ink 则在 `TianshuSidebar.module.css` 中局部重绑，因为全局覆盖会重绘整个应用。

浅色主题的列是浅色表面，其局部重绑为玻璃上的深藏青 ink；暗色主题通过 `body[data-ds-dark-theme]`（ui-theme 的暗色权威信号）把同一批 token 重绑回白色族，因为暗色列仍是暗表面上的半透明藏青。列同时施加 `backdrop-filter: blur(18px)`，窗口在列后绘制的任何内容都呈毛玻璃观感。暗色取值保持列的可读性，而非复用浅色玻璃——后者会造成深色叠浅色的失效文字。

## 侧边栏

`sidebar` 是 `single` 插槽，注册进去会**顶替**上游外壳而非叠加；web-app bundle 相应禁用了 `ui-sidebar` 行。本包重新声明了同样的三个座位——`sidebar.workspaces`、`sidebar.settings`、`sidebar.footer.action`——因此 [ui-workspace](../ui-workspace/README.md) 的浏览器与 [ui-settings](../ui-settings/README.md) 的底部座位原样可用。

该列逐字保留了上游外壳的结构性行为：折叠是滑移加交叉淡出进入布局所属的 56px 轨道，内容在淡出期间冻结于展开宽度以避免滑移途中回流，滚动条是指针可见性附属物——指针不在时会把 ui-theme 的滚动条间接绑定移开。在此之上新增了导航块（配置 / 任务管理 / 会话管理），位于「新建会话」与浏览区之间。

导航行会打开本包所拥有的管理界面。选中态是跨注册项的状态——侧边栏与页面是两个注册项——因此它存放在一个声明的 store 中，二者从 `apply` 获得同一个句柄；再次点击已打开的行会将其关闭。它不做持久化：你当时停在哪个页面属于单次访问的事实，在全新加载时恢复它只会遮住产品本应打开的会话。

`TianshuPages` 注册进 `shell.overlay` 而非 `conversation`：后者是 ui-conversation 所拥有的单一插槽，占用它会顶掉整个聊天界面。overlay 覆盖整个框架，因此页面是一个双轨网格，第一轨属于侧边栏——留空且点击穿透，因为关闭页面的导航就在那里。该轨的宽度取自 `--dsh-tianshu-sidebar-width`，由侧边栏依据框架已经交给它的宽度发布，因此拖拽或折叠时页面会随该列移动，且无需在别处重述宽度。页面能够诚实展示的内容受限于宿主实际具备的能力；参见 Known Limitations。

该列带有 `data-dsh-sidebar-root` 与 `data-dsh-sidebar-wide`。它们是供宿主外壳定位的布局锚点，而非样式钩子：桌面客户端的 Windows 标题栏通过 root 测量该列，并在展开时为其补足上边距；它按属性查找，找不到时静默返回。去掉它们会让该布局失效且任何地方都不会报错，因此有测试将其钉住。

`TianshuSidebarComponentProps` 组合了布局 owner 份额、框架会话钩子、三个声明的子插槽，以及注入的 `startSession` 与折叠回调。本包没有插件 store。

`/client` 只导出插件体（`apply`/`inject`）与契约类型；组件与 token 表保持包内私有。

## Model Experience

None, as this package renders browser chrome; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **任务管理的模板中心仅为呈现** —— 三张模板卡片渲染的是固定文案，并不能创建任何东西，因为宿主没有可供创建的模板概念。页面就地说明了这一点，而不是暗示正在加载。要让它们成真需要宿主侧能力，而非在此处改动。
- **任务管理不列出任何任务** —— 宿主的定时能力是会话内、模型可见的提醒（`after`／`at`／`every`），而不是参考设计所展示的跨会话任务表。没有全局对象可供枚举，因此该区块诚实地留空；真正的任务表属于新的宿主能力。
- **会话管理的删除只是软删除** —— 页面承载了协议提供的每一个动作（打开、重命名、归档／取消归档、归入文件夹、删除到回收站、还原），但被删除会话的日志仍留在磁盘上，因为会话持久化没有暴露删除行记录的能力；在宿主具备该能力之前，回收站没有彻底删除或清空的操作。行菜单中的删除是两步确认，回收站中的行只提供还原，因此本界面上的任何控件都不会指向宿主不具备的能力。
- **会话管理没有搜索、排序或批量选择** —— 各行沿用框架按宿主顺序的投递；筛选只按归档状态与文件夹进行。会话搜索在协议上是存在的（`sessions.search`），但在列表长到需要它之前，这里暂不接入。
- **专家套件的安装不会实时刷新当前会话的 `/` 菜单** —— 安装会写入用户 skill（技能）根目录，文件系统提供方在下一次扫描时发现它；该扫描再次触发时 composer 菜单才更新，而页面不会强制触发。**没有当前会话时，技能回退到内置目录** —— 宿主唯一列出 skill 的 RPC 是按会话寻址的，因此无会话的视图展示本地表（其余情况由宿主行接管，中文标题按名称从本地表合并而来）。
- **技能渲染的是内置目录，而非宿主列表** —— 五个内置 skill（含分类与详情正文）是一张 UI 本地表；宿主按会话提供的只读 `skill.list` 通道接入后会取代它，届时本地分类让位于宿主的 `source` 词汇。「发送到对话」通过限定作用域的插入文本事件把内容预填进当前会话的 composer——与从菜单选取走的是同一条路径——并在没有当前会话接受它时保持页面打开。
- **MCP 不列出任何服务器** —— 每个 mcp-client 实例对应 profile 的 cordis.yml 中声明的一台服务器，且没有任何一台默认启用，因此页面说明服务器如何接入，而不是渲染一份编造的清单。服务器管理界面属于宿主尚不具备的能力。
- **连接器指向设置页已在管理的提供方** —— 宿主今天可接入的外部服务就是凭据存放在设置页中的模型提供方；专门的连接器域暂缓。
- **文字字标是内嵌字体子集** —— `TianshuMarks.module.css` 内嵌了恰好覆盖「天枢平台TIANSHUPLATFORM」的 woff2，子集自思源宋体 CN Heavy（SIL OFL），原因在于本包不携带资源管线。字标文字一旦扩展需重新生成子集（`pyftsubset --text=… --flavor=woff2`）；其余码点回落到系统字体栈。
- **列内 ink 按规则重绑，未经逐项审计** —— 样式表反转了嵌套界面预期会读取的 ink、边框与交互 token 族。若某个贡献者注册进 `sidebar.workspaces` 时使用了这些族之外的 token，仍可能在蓝底上出现深色文字。
